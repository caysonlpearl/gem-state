# Vehicle price insights

Eligible private seller cars/trucks include price insights automatically. Dealerships start enabled and can switch the feature off in `/dealer-setup`; the server checks their saved setting before reading any estimate cache or calling a provider. Third-party dealer inventory without a linked Bluebird dealership is not rated. Missing year/make/model/mileage/location, demo/ended listings and known branded titles are excluded. The public request accepts only a listing ID and resolves all vehicle, price and dealer details on the server.

Apply `20261111013000_vehicle_price_insights.sql` before publishing the application. Three service-role-only tables persist derived estimates, refresh leases, provider cooldowns and an append-only request ledger. Lifetime counts must not be purged or reset when a calendar month changes.

## Provider order and credentials

1. Vehicles.dev: server secret `VEHICLES_API_KEY`. Defaults to a 250-call **lifetime** cap and 250-call monthly cap. The new Bluebird account used two manual verification requests, so its deployed `VEHICLES_VALUATION_LIFETIME_LIMIT` is **248**. Other adapter verification requests reserve from the same integration ledger. The free allowance is shared across all eligible account operations; further manual/API-key usage must also reduce this cap. There is no purchased credit balance or automatic top-up. Calls use the market-value endpoint, not the separately paid Price Check endpoint.
2. VinAudit: `VINAUDIT_API_KEY` plus `VINAUDIT_VALUATION_PRODUCTION_ALLOWED=true`, only after its license permits the intended live display. Its advertised 100-query trial is for evaluation/testing, not an assumed production entitlement. Default lifetime cap 100 and monthly cap 250. Requires a valid VIN, used condition, matching mileage, retail estimate and sufficient comparable data. The adapter is prepared; a production-authorized account/key is still needed.
3. MarketCheck: existing `MARKETCHECK_API_KEY` plus `MARKETCHECK_VALUATION_PRODUCTION_ALLOWED=true`. Free accounts expressly prohibit use as a production data source. Set positive `MARKETCHECK_VALUATION_LIFETIME_LIMIT` and `MARKETCHECK_VALUATION_MONTHLY_LIMIT` only after licensing and spend are authorized; lifetime defaults to zero. Requires a used vehicle, VIN and actual franchise/independent dealer type (collected in dealership setup). No class is guessed for private sellers. Valuation calls also reserve from the existing shared MarketCheck monthly account budget.

Every provider supports `<PREFIX>_VALUATION_LIFETIME_LIMIT` and `<PREFIX>_VALUATION_MONTHLY_LIMIT`; zero disables calling it. Requesting the feature never opts an account into a paid plan, purchases credits, enables a backup entitlement or increases caps. When eligible providers reach their caps, the chain tries the next authorized provider. With none available, the insight box is omitted; the listing remains usable. Cached results can continue within their freshness window.

## Display and verification

Estimates are cached for up to seven days across repeat views. Identity, mileage, trim, condition and dealer classification are part of the cache key; asking price is intentionally excluded so a price change updates the comparison without another API call. Failed lookups cache a null result for five minutes. An atomic 90-second lease prevents concurrent refreshes; atomic per-provider budgets prevent parallel overages. HTTP authentication/payment/quota failures block further calls to the affected provider and allow licensed backups. Reservations conservatively count attempted requests, including failed attempts. Known crawler/preview user agents do not trigger valuation calls, and server rendering does not run them.

Vehicles.dev's live response includes input coverage and a source-data date. Only `in_domain` estimates with matching inputs and source data no more than 90 days old are accepted. Model-wide median error is not shown as individual vehicle confidence. Comparisons use a neutral band of at least 10%, widened to twice the reported model error. They describe an estimated **retail asking price**, not a sale price, appraisal, condition certification or MSRP discount. The source and method appear inline; the check date reflects estimate retrieval. Source-data freshness remains enforced server-side. Other providers retain their own documented methodology.

Run `node --experimental-strip-types --test tests/vehicle-price-insights.test.mjs`, `npx tsc --noEmit`, `npm run build`, and the existing release checks. Provider contract, quota, cache, dealer opt-out, fallback and real PostgreSQL permission/lease tests use no paid API requests. A live browser check must separately verify the published secret, estimate box, repeat-view cache and dealer setting.

## Visual comparison and vehicle specificity

This revision changes the card presentation only. The existing point-estimate provider, cache, quotas, dealer opt-out and refresh behavior are unchanged. No comparable-listing search is called. The card leads with a clear verdict and rounded percentage in a pill, displays the existing estimate approximately to the nearest $100, and uses a brighter red/yellow/green comparison scale. The ribbon is removed; the backwards-hat mascot is a small header mark. Three text sizes (24px number, 14px verdict/header, 12px supporting text), one white surface, consistent left alignment and a compact header organize the card. The method is visible inline under “About this estimate.” No range or comparable count is invented when the current response does not provide one.

Market-value requests include year, canonical model casing, make, trim, actual mileage, uppercase state, and new/used/CPO status. Where present, recognized drivetrain, fuel, transmission, body style, base exterior color and MSRP are also sent. Unknown features are omitted, never invented. Vehicles.dev responses must echo condition along with the existing identity/location/mileage checks. Optional features echoed differently are rejected; optional features omitted by the model are recorded as unconfirmed and are not displayed as estimate factors. This accommodates models that accept the parameters without scoring those features. A v2 cache namespace avoids reusing estimates computed before these validations. VIN is available for licensed VIN-based fallbacks; Vehicles.dev market-value uses the attribute identity rather than a VIN. “About this estimate” exposes the inputs and explains that mechanical wear, history, options and fees are not certified by this estimate.

KBB has a licensed InfoDriver Price Advisor widget, requiring an InfoDriver subscription and approval of placement. No KBB marks or valuation data are used by this implementation.
